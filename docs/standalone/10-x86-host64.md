# Fase 10 — x86 carrier + Host64

## Objetivo

Permitir execução x64 para jogos 32-bit sem manter `HostServer64.cpp`/capture como novos monólitos.

## Dependências

Fases 03 e 07.

## Fora de escopo

- Runtime completo em x86
- Pixels no named pipe
- Assumir D3D11 x86 como prova de todas APIs

## Implementação

- [ ] Reusar CaptureProvider32/HostServer64 e testes existentes.
- [ ] Antes de expandir `HostServer64.cpp`, separar session/protocol/worker/resource-import por responsabilidade.
- [ ] Separar capture hook específico da API do IPC comum.
- [ ] Preservar DummyCopy como prova barata.
- [ ] Versionar IPC/session generation.
- [ ] Transportar só control + handles + fence values.
- [ ] Tratar disconnect/crash/game exit/stale messages.
- [ ] Policy/model só Host64.
- [ ] Todo código x86/x64 novo/tocado <=300 linhas por arquivo.

## Revisão obrigatória

- [ ] Cada HANDLE tem creator/target/consumer/close.
- [ ] Reconnect não reutiliza generation.
- [ ] Sem wait infinito.
- [ ] IPC não transporta pixels.
- [ ] Splits não criam protocolo duplicado entre client/server.

## Validação rápida

- [ ] Handshake/pipelined/DummyCopy existentes.
- [ ] Win32→x64 real; same-bitness não conta.
- [ ] Stress disconnect/stale IDs.
