# Fase 10 — x86 carrier + Host64

## Objetivo

Permitir execução DLSS 5 x64 para jogos 32-bit sem duplicar o runtime pesado.

## Dependências

Fases 03 e 07.

## Fora de escopo

- Runtime completo em x86
- Pixels no named pipe

## Implementação

- [ ] Reusar CaptureProvider32/HostServer64 e DummyCopy como primeira validação.
- [ ] Versionar IPC e session generation.
- [ ] Transportar apenas controle + shared handles + fence values.
- [ ] Definir producer/consumer ownership e close rules.
- [ ] Tratar disconnect, host crash, game exit e stale messages.
- [ ] Policy/model permanecem no Host64.
- [ ] Criar Harness32 mínimo que usa o mesmo scenario protocol.

## Revisão obrigatória

- [ ] Cada HANDLE: creator, DuplicateHandle target, consumer e CloseHandle.
- [ ] Reconnect não reutiliza session antiga.
- [ ] Nenhum wait infinito; timeout/failure vira status explícito.
- [ ] IPC payload nunca carrega frame pixels.

## Validação rápida

- [ ] Harness32↔Host64 DummyCopy sem GPU NVIDIA.
- [ ] Stress disconnect/reconnect e handle reuse.
- [ ] Long run de work/session/fence IDs.
- [ ] Depois trocar DummyCopy por Neural em hardware compatível.

## Gate

- [ ] Transporte e lifecycle validados sem jogo real.
- [ ] Sem handle/fence leaks.
- [ ] Bitness deixa de ser blocker do core.
