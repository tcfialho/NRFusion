# Fase 10 — x86 carrier + Host64

## Objetivo

Permitir execução DLSS 5 x64 para jogos 32-bit sem duplicar o runtime pesado.

## Dependências

Fases 03 e 07.

## Fora de escopo

- Runtime completo em x86
- Pixels no named pipe
- Assumir que o Capture32 D3D11 atual já cobre todas as APIs x86

## Implementação

- [ ] Reusar `CaptureProvider32`, `HostServer64`, `ipc_host_test` e roundtrip existentes.
- [ ] Preservar DummyCopy como prova barata de transporte antes de envolver DLSS.
- [ ] Versionar IPC e session generation.
- [ ] Transportar somente controle + shared handles + fence values.
- [ ] Definir producer/consumer ownership e close rules.
- [ ] Tratar disconnect, host crash, game exit e stale messages.
- [ ] Policy/model permanecem no Host64.
- [ ] Generalizar o carrier por API somente quando cada frontend x86 for implementado; D3D11 atual não prova Vulkan/OpenGL/D3D9/D3D10 x86.

## Revisão obrigatória

- [ ] Cada HANDLE: creator, processo alvo, consumer e close path.
- [ ] Reconnect nunca reutiliza generation anterior.
- [ ] Nenhum wait infinito; timeout vira status/fallback.
- [ ] IPC nunca carrega pixels.
- [ ] x86-specific code permanece fino.

## Validação rápida

- [ ] Reusar handshake/pipelined/DummyCopy tests atuais.
- [ ] Stress disconnect/reconnect e stale IDs.
- [ ] Executar o verdadeiro Win32→x64 roundtrip; same-bitness não conta como cobertura x86.
- [ ] Neural real somente em hardware compatível.

## Gate

- [ ] Transporte/lifecycle x86 validados independentemente do modelo.
- [ ] Sem handle/fence leaks.
- [ ] Cada API x86 recebe status próprio de qualificação.
